# M1 音频试听：运行、审核与后续部署

本阶段停在试听准备。已交付页面、固定样本计划、资源接口和生成脚本；缺少 API 凭据，真实音频为 **0 / 96**。不会以空文件或浏览器 TTS 冒充神经网络 MP3。用户选定 US / UK 音色前不批量接入。

## 运行页面

在项目目录，使用 Node **24** 与 pnpm 11：

```powershell
node --version
pnpm audio:plan
pnpm dev
```

打开 `http://localhost:5173/#/audio-lab`，或词典页底部“发音试听室”。iPhone 同一 Wi-Fi 用电脑 WLAN 地址 `http://电脑IP:5173/#/audio-lab`。本地 LAN 可做 Safari 页面测试；PWA 主屏幕验收用可信 HTTPS 部署。

本次发现系统默认 Node 已变为 26.13.0，项目仍约定 Node 24；验证时使用已有 24.22.1，没有升级依赖。当前 PowerShell 如需切回已安装版本：

```powershell
# 运行前请确认 PATH 上的 node 为项目要求的 Node.js 24。
node --version
```

这只影响当前终端，不修改系统设置。`pnpm audio:plan` 不调用 API，会重建计划并保留已有 SHA-256 验证通过的生成文件及审核状态。

## 安全配置与小样生成

脚本使用 Node 内置 fetch，无需新增 SDK。密钥只读本地进程环境；PWA 不调用 Azure/Google。不要把密钥发到聊天、写在命令参数、`src/`、`public/`、`dist/` 或任何 `VITE_` 变量中。`.env.*` 已忽略，但忽略规则不等于加密。

### Azure 优先试用

在自有 Azure 账户创建 Speech **S0 付费层**资源，记录区域（例如 eastus）并检查该区价格和音色。F0 每月额度不等同于付费层输出使用权，详情见 [供应商报告](M1-音频供应商评测.md)。当前脚本要求声明 S0；此声明不能自动验证云账户实际层级。

在本地 PowerShell 输入，不会把真实密钥写进命令历史：

```powershell
$speechSecret = Read-Host 'Azure Speech key（只输入本地终端）' -AsSecureString
$env:AZURE_SPEECH_KEY = [System.Net.NetworkCredential]::new('', $speechSecret).Password
$env:AZURE_SPEECH_REGION = 'eastus'
$env:AZURE_SPEECH_TIER = 'S0'

# 先预估，不发送请求
node scripts/generate-audition.mjs --provider azure --limit 8
# 确认该小样预算后执行，最多 8 个尚未生成文件
node scripts/generate-audition.mjs --generate --provider azure --limit 8 --budget-usd 0.25

Remove-Item Env:AZURE_SPEECH_KEY
Remove-Variable speechSecret
```

也可自行将配置放在本机 `.env.audio.local`，用 `node --env-file=.env.audio.local scripts/generate-audition.mjs ...`。不要提交或上传该文件；当前交付没有创建任何包含密钥的文件。

### Google 对照试听

自有项目启用 Cloud Text-to-Speech API 和计费，使用有调用权限的本地 Google Cloud CLI 登录账户。获取短期 OAuth token；不要下载服务账户私钥到前端目录。调用方式依据 [官方 REST 说明](https://docs.cloud.google.com/text-to-speech/docs/basics)。

```powershell
gcloud auth login
$env:GOOGLE_CLOUD_PROJECT = '你的项目ID'
$env:GOOGLE_ACCESS_TOKEN = (gcloud auth print-access-token)
node scripts/generate-audition.mjs --provider google --limit 8
node scripts/generate-audition.mjs --generate --provider google --limit 8 --budget-usd 0.25
Remove-Item Env:GOOGLE_ACCESS_TOKEN
```

本轮没有替你登录、创建云资源或验证 gcloud 已安装。401/403 时检查登录、token 有效期、项目权限/计费/API；脚本不记录服务端响应正文或请求头。

筛选单音色可加 `--voice en-US-JennyNeural`（或清单中的完整候选名）。若需要补齐**试听清单**，先 dry-run，再分别使用 `--provider azure --limit 48 --budget-usd 0.5` 与 `--provider google --limit 48 --budget-usd 0.8` 加 `--generate`；这仍仅限固定 12 段评测材料，不是词典批量生成。不同区域价格用 `--usd-per-million` 调整。

### 文件与失败行为

- 输出 MP3：`public/audio/audition/<音频内容SHA-256>.mp3`；清单：`public/data/audio-audition.json`。不生成文件时没有音频 URL。
- 请求身份包含内容/义项/读音 ID、全文、地区、提供商、模型、音色、IPA 和配方版本。更新配方时必须增加 `recipeVersion`，不能覆盖既有审核对象。
- 重跑只跳过本地文件长度与 SHA-256 都符合的资源。损坏/缺失会成为待生成项；同名不同读音不共享请求身份。
- 仅 429 / 5xx 有限退避，最多三次尝试。遵守 Retry-After；要求等待超过 30 秒就停止。401/403、无效输入、网络异常和无法识别的 MP3 不盲目重试；修复后人工重跑。
- 第一项最终失败就停止整个运行，保留已成功文件。原子替换清单；跨进程锁防止并发覆盖。强制中断若留下 `artifacts/audio-generation.lock`，先确认没有生成进程再移除此单个锁文件。
- 每次成功仍标 `review=pending`。MP3 头检查仅排除明显错误响应，不证明完整解码或音质；人工试听不可省略。
- 使用 `pnpm dev` 时生成后刷新即可；预览/已部署页面须重新 `pnpm build` 并重新上传 `dist`。

## iPhone 人工试听与音色选择

先完成每家前 8 个文件，确保按钮从“尚未生成”变成“播放候选音频”。分别在 Safari 与 PWA 用扬声器、耳机，以正常音量试听。所有候选都需确认与展示文本一致，不能只听开头。

| 检查项 | 记录方式 / 合格条件 |
| --- | --- |
| 设备条件 | iPhone 型号、iOS 版本、日期、Safari/PWA、网络、扬声器/耳机 |
| 单词 | create / creative / creativity 重音、辅音尾、音节清楚，无漏音或额外音 |
| 短语 | make sense 连读自然，sense 尾部完整 |
| 多音词 | record 名词首音节重音、动词后音节重音；read 原形 /riːd/、过去式 /rɛd/；各自独立记录 |
| 长句 | 标点处停顿合理，专有名词另核验，句子完整，无词语增删 |
| 声音质量 | 无电音、失真、发闷、爆音、过长空白或卡顿；与设备音量问题区分 |
| 调速 | 1× 作为音色比较基准；再试 0.75× 与 1.25×，检查变速失真 |
| 交互 | 重复点击只留一个播放；US/UK 切换、返回、停止、后台隐藏取消旧声音；断网失败有提示 |
| 备用 TTS | iOS 缺少匹配音频时不自动合成；主动点“本次使用备用 TTS”后才播放；下次播放仍需主动选择 |

每个候选的“记录听感与来源”可保存本机笔记并导出 JSON。满意仅为候选评分，不会自动生成正式审核或上传数据。最终反馈模板：

```text
设备 / iOS / Safari 或 PWA / 扬声器或耳机：
US 首选音色（完整名称）：
UK 首选音色（完整名称）：
未通过的样本 ID、问题、是否需改 IPA / 停顿：
是否同意下一增量为现有 M1 内容预生成（预算另列）：
```

## 选定后才做：批量与 Cloudflare

1. 审阅导出的逐样本记录，固定 US/UK 音色与配方；重新核验单词真人录音的具体读音，不能只凭拼写或许可判为正确。音色满意不代表全部义项音频通过。
2. 为现有 10 词、短语及 95 条例句建立独立批量计划与成本清单，区分多音词；取得本轮用户后续授权后再生成。当前脚本只有试听白名单，不具备整库开关。
3. 逐条试听、记录 reviewer/date/device/notes；只把 `ready + approved` 资源放入正式 manifest。现有 `entry-default` 录音仅沿用 M1 行为，不能自动分配给未来新读音或义项。
4. 小规模先将 MP3 随 `dist/` 放到 Cloudflare Pages。`pnpm test`、`pnpm build`、`pnpm test:e2e` 后，Cloudflare 控制台 Workers & Pages → Pages → Direct Upload，上传构建目录，取得 HTTPS 地址并打开 `/#/audio-lab`。已有项目可上传新的部署；不要上传整个仓库或本地配置。参见 [Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)。本轮没有执行部署或创建线上地址。
5. 迁移 R2 时保持 `audio/audition/<hash>.mp3` 等 object key，核对数量/长度/哈希与 `Content-Type: audio/mpeg`，设不可变资源缓存。使用 HTTPS 自定义域名，设置允许应用源站的 GET/HEAD CORS，检查 Range/206 与 iPhone 连续播放。参见 [R2 公共访问](https://developers.cloudflare.com/r2/buckets/public-buckets/)及 [CORS](https://developers.cloudflare.com/r2/buckets/cors/)。
6. 构建时设置公开配置 `VITE_AUDIO_ASSET_BASE=https://音频域名/`，重建部署；只有资源层拼接地址，词典详情无需改写。此变量只能放公开基础 URL。正式 manifest 与署名仍随站点发布；试听数据不应误进入正式播放队列。迁移真实网络与 iPhone 验收仍待执行。

## 当前验证边界

脚本有无需凭据的单元测试和 dry-run，HTTP 适配测试使用测试替身；没有真实供应商 API 成功记录。页面使用共享播放器验证资源选择、错误和取消；测试音频字节只存在测试临时目录或内存，未写入公开音频目录。声音品质、Google Preview SSML 的地区支持、API 账户权限和实际成本均待配置后验证。查看 [本轮验收](M1-音频升级验收.md)。
