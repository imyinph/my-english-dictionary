## 真实网络探测

2026-11-10 的探测只读取响应前 64 字节，确认 HTTP 状态及音频 Content-Type，**没有试听、解码或 iPhone 验证**。证据保存为 [网络记录](M1-audio-network-2026-11-10.json)。

- 4 个录音地址可达：create US、creative UK、creator US、creativity US。
- 其余 9 个遭遇 HTTP 429 限流或机器人策略拒绝，不能判定为可用，也不据此认定文件永久无效。
- 不再重试这批地址；探测脚本已修正为首次 429 后跳过剩余项目。正常应用按用户点击尝试音频并回退 TTS。
- `creation` 未启用录音：作者元数据只有推定署名；这个词使用 TTS，不把其授权状态写成已验证。

本轮测试用浏览器未检测到可用地区 TTS 声音。自动化通过来自明确的 API 替身，不能证明这台机器或 iPhone 的原生语音可听。录音可达性、原生 TTS 出声及真实播放质量仍是验收开放项。

## 本地验收步骤

运行 `pnpm dev`，打开 <http://localhost:5173/>。

1. 搜索 `create`：看见真实 Wiktionary 义项及音标。展开“内容来源、许可与录音署名”，检查原文、贡献历史、Kaikki JSONL、文本许可和录音作者。
2. 搜索 `creation`：中文“創作品 /创作品”默认隐藏。展开后点击 Word Family 的 `creative`，再返回，中文应重新隐藏。例句译文显示缺失而非 M0 翻译。
3. 搜索 `created`：进入 `create` 并保留查询形式；`creative` 应仍是独立词条。
4. 从 `make` 的短语区打开 `make sense`，刷新，点击关键词再返回；短语仍拥有独立路由。
5. 检查 `creatively`：没有可复用例句时明确显示缺失，不出现编造句子。
6. 默认 US 点击 `create` 发音：若录音可达，应显示真人录音状态；不可达时显示回退原因。检查当前按钮旁也可见反馈。
7. 切换 UK，朗读 `make sense` 和例句：没有 UK 录音时只选择 en-GB TTS；系统没有对应声音必须报错，不应静默播放 US。
8. 选择 0.75×，播放例句；刷新后口音、速度应保留。切换设置、导航或停止应结束旧播放。
9. 模拟断网或禁用系统语音后再次播放，检查错误可理解且能重试；恢复后不需要重新加载测试数据。
