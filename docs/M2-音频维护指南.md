# M2 音频维护指南

## 本机启动与身份

当前生成区域统一为 **ap-southeast-2（悉尼）**，Profile 为 **dictionary-polly**。生成器默认值、配置助手和测试配置已同步；现有 Profile 的 region 也是悉尼。`--region` 优先于 AWS_REGION / AWS_DEFAULT_REGION，未设置时用项目默认值。

在项目目录使用 Node 24、pnpm 11：

```powershell
# 运行前请确认 PATH 上的 node 为项目要求的 Node.js 24。
pnpm install --frozen-lockfile
pnpm dev
```

打开 http://localhost:5173/，诊断页为 `/#/audio-lab`。本地网络地址可测试 Safari 页面；PWA 安装验收必须 HTTPS。

脚本通过 AWS SDK 标准凭据链读取身份，可用 `--profile dictionary-polly` 或 `AWS_PROFILE`；环境变量身份也支持。未配置时，可自行运行 `./scripts/configure-aws-profile.ps1`，按本机隐藏提示输入，写入用户目录 `.aws`，不会输出密钥，不覆盖同名 Profile。也支持 AWS CLI / IAM Identity Center 已配置的 Profile。

当前 Profile 已存在，不需重复运行配置助手。缺权限时把 `config/polly-iam-policy.json` 用作 IAM 权限策略，授予 DescribeVoices / SynthesizeSpeech，不需要 S3。动作/Resource 对照见 [AWS 权限表](https://docs.aws.amazon.com/polly/latest/dg/api-permissions-reference.html)。预检查成功只证明身份与音色查询可用；实际合成权限由首个计入预算的请求验证。

密钥不可写进 `.env` 的 VITE_ 变量、源码、public、dist、CLI 参数或聊天。轮换时在 AWS 创建/更新本机身份，更新标准凭据文件或使用 CLI 配置；预检查成功后禁用旧凭据。不要删除本地音频日志来“重置”花费。

## 增量维护

```powershell
pnpm audio:plan
pnpm audio:preflight --profile dictionary-polly
pnpm audio:generate --profile dictionary-polly
pnpm audio:verify
```

新增内容必须先经词典范围/来源审核；本任务不擅自扩词。更新已批准的数据后，planner 自动扫描可播放字段。文本/规则/音色/引擎变化产生新 ID，未变资源先查文件哈希，不再付费。ID 或上游义项排序变化须人工核对映射。

默认跳过永久失败；修复原因后 `pnpm audio:generate --profile dictionary-polly --retry-failed`。Ctrl+C 会停止新请求，已完成文件保留。未确定服务端结果的任务列为 INTERRUPTED_UNCERTAIN；检查日志/账单后才使用 `--retry-uncertain`，可能重复付费。`--limit 2` 可限制本次请求任务范围；预算默认 5 美元，不能因为有 Credit 绕过限制。

保留 `.audio-state/polly/ledger.jsonl`、receipts 与 public 音频备份。硬终止若留下 generation.lock，先确认没有该项目生成进程再删除这一个锁文件；不要删整个状态目录。损坏日志会中止，不自动忽略费用记录。MP3 临时文件通过完整帧结构检查后原子重命名，失败不会先删除旧文件。

## 定点纠音与人工审核

`config/polly-pronunciations.json` 当前 rules 为空，不自动从词典 IPA 覆盖语音。确有问题时增加规则，字段为 target（contentId/kind/senseId?/pronunciationId）、expectedText、version、ipa、sourceUrl、reviewedBy、reviewedAt。必须有可信读音来源和人工确认；IPA 通过 Neural 支持的 phoneme SSML 使用，不改 UI 拼写。

词头默认 pronunciationId 为 entry-default；例句为 sentence-default 且须带其 senseId。需词性/义项特定读音时指定词条 ID、对应 senseId 和独立 pronunciationId，详情会显示该义项读音按钮。不带义项的词头音频不充当所有同形异音读法。改规则版本只重建对应双音色，生成后再试听。

逐条验收结论写入对应 `.audio-state/polly/receipts/{id}.json` 的 review（status、reviewer、reviewedAt、device、notes），再运行 audio:plan 发布清单。rejected 资源在播放器中禁用，须纠正配方并生成新文件；不要把所有 pending 一键标为 approved。保存好原始声音版本，因为 AWS 没有暴露可固定的内部音色修订号。

## 测试与发布到现有 Cloudflare 项目

```powershell
pnpm test
pnpm release:build
pnpm test:e2e
pnpm audio:verify-media
```

正式构建要求全部 210 条资源 ready；普通 pnpm build 允许开发缺失回退。浏览器测试自动启动 4173，请保持端口空闲。构建产物仅上传 dist，不上传项目根目录或 `.audio-state`。部署前不要绕过 release 检查。

目标项目：**my-english-dictionary**。用户给出的 `651e2c06...pages.dev` 是具体部署快照，新部署会得到新 ID；不能覆盖为同一个快照地址。可使用现有 Cloudflare 登录在 Workers & Pages 中选择该项目上传 dist，或按 [Wrangler Pages 命令](https://developers.cloudflare.com/workers/wrangler/commands/pages/)：

```powershell
pnpm dlx wrangler@4 login
pnpm dlx wrangler@4 pages project list
pnpm dlx wrangler@4 pages deploy dist --project-name my-english-dictionary --branch m2-audio
```

本轮已通过 Cloudflare 查询确认实际 production branch 为 `main`，用户完成本机 OAuth 授权后，已用 Wrangler 4.160.1 发布正式 M2。上面的 `m2-audio` 仅用于今后的预览分支；正式更新使用 `--branch main`。不上传凭据、项目根目录或本地费用日志。

当前正式入口：[my-english-dictionary.pages.dev](https://my-english-dictionary.pages.dev)；固定 M2 快照：[b92bfee6.my-english-dictionary.pages.dev](https://b92bfee6.my-english-dictionary.pages.dev)。以后从稳定入口安装 PWA 可以随正式发布更新；旧快照上的安装不会自动改变站点域名。

本地 `pnpm audio:verify-media` 在 4175 端口启动构建预览，逐文件真实解码，并通过原生 Audio 播放两个音色的词头、短语和例句。远程验证：

```powershell
node scripts/verifyDeployment.mjs https://b92bfee6.my-english-dictionary.pages.dev
pnpm audio:verify-media --url https://b92bfee6.my-english-dictionary.pages.dev
```

前一个命令检查线上全部文件哈希、类型、缓存与 Range 行为；后一个验证真实页面播放事件，不代替人工听审。结果保存在 artifacts 中。Pages 当前对 Range 返回完整 HTTP 200，见 [官方 Serving Pages](https://developers.cloudflare.com/pages/configuration/serving-pages/)；脚本明确记录完整文件回退，不能称作 206 通过。真机如出现加载/拖动问题，再依已保留的资源根地址接口评估 R2，不为此擅自增加实时后端。

检查新地址首页、`/data/audio-manifest.json`、两个音色的词/短语/例句 MP3 HTTP 状态与 Content-Type、文件字节/哈希、缓存响应头，再在 iPhone 验收。音频按需获取，无全量预缓存。保留旧部署可回退；确认无旧清单引用前不清理历史哈希文件。路径前缀部署时保留完整目录及 BASE_URL 配置。

R2 迁移方法见实现说明；只改变资源根 URL，不更改详情页或添加实时 AWS 服务。

## 正式录音的倍速文件

默认 1× 直接播放原 MP3。0.5×、0.75×、1.25× 使用 FFmpeg atempo 离线处理后的文件，保留原音高，播放器以 1× 播放相应文件。两种音色、词头、短语、例句和诊断页共用同一个映射。变速文件按内容哈希存放在 public/audio/rates，映射位于 content/audio-rates-v1.json。

更新原音频后运行 `python scripts/audio_rates.py --ffmpeg <FFmpeg可执行文件路径>`。构建会分别校验 public 和 dist 中的原声与全部倍速文件。发布后运行 `node scripts/verifyPlaybackRates.mjs https://my-english-dictionary.pages.dev/`，在 Chromium 和 WebKit 分别测量同一句、两种音色、四档速度从 playing 到 ended 的真实时长。
