## 5. 中文缺失原因与匹配风险

### 5.1 词义中文：源翻译不是逐义项中文释义库

adapter 的 `chinese()` 只接收 cmn/zh，优先义项内翻译，否则要求源翻译的 sense 描述与当前**最后一条 gloss**归一化后完全相同。归一化只处理大小写、空白和末尾有限标点，不做语义猜测。

例如 create 的源翻译标注 `to put into existence`，当前首义项是 `To bring into existence; (sometimes in particular:)`。它们值得送审，但不是字符串精确匹配。直接放宽为按词头或模糊子串会把中文套到不同词性/义项；make 有 60 个义项，风险尤其明显。

因此 **29 条未匹配是候选内容，不是 29 个已补全义项**。应生成带词性、完整 gloss 链、标签、例句和来源定位的候选映射，唯一性及上下文审核通过后才能发布。不把候选检索置信度当人工批准。

### 5.2 例句中文：实际源缓存无译文，代码也没有传递链路

当前十词英文源缓存的可复用 example 没有中文翻译；不是单纯隐藏了现成译文。同时，`import_kaikki.py` 投影例句只保留 text/type/bold_text_offsets/tags，adapter 创建 Example 也未设置 translation。即便未来上游出现翻译，现代码不会自动可靠接入。

M3.1 要补上独立 exampleId + senseId 的中文记录及读取链路；不能只替换 UI 文案就宣称“全部例句已有翻译”。现有 TypeScript 的 `translation?: string` 仅证明字段可容纳文本，测试中的示例译文也不是生产内容。

### 5.3 来源与状态不独立

Sense/Example 的 source 当前描述英文 Wiktionary 内容，中文只是一段可选字符串。它无法表达中文由哪个源行、AI 模型或人工修改产生，也没有审核时间、失效理由或版本。若直接把 AI 中文填进该字符串再显示统一 Wiktionary 来源，会误导用户。

### 5.4 ID 含源数据位置

当前计算为 `entryId:pos:(etymology_number 或 recordIndex):hash(glosses):senseIndex`；exampleId 是 senseId 加句子指纹。

仅在内存中反转记录顺序，**53 个义项 ID 改变**；仅反转各记录的义项顺序，**102 个义项 ID 改变**。本轮没有将反转数据写回磁盘。当前 ID 在固定快照中可用，不能称为跨上游版本稳定身份。

## 6. 建议的数据结构与中文补全方案

以下均是待确认的设计，不是已新增的生产文件或功能。

### 6.1 三类数据分离

| 层 | 建议内容 | 写入主体 |
| --- | --- | --- |
| 原始词典 | 现有 English snapshot 与 M2 音频；后续 identity registry | 受控本地导入流程，本次不改英文与音频 |
| 中文内容 | 独立 `chinese-content.json`，源引用、草稿、审核版本；本机内容审核记录 | 本地补全工具；审核页导出后经校验发布 |
| 个人学习数据 | 收藏/学习状态、复习卡片/事件、文章/选择与用户设置 | 浏览器 IndexedDB Repository；不写回词典 JSON |

建议中文文件使用自己的 schemaVersion、dictionaryVersion（源快照哈希）与 contentRevision，不抬高现有 Kaikki schemaVersion 或挤进 M2 音频清单。

### 6.2 保持身份的办法

1. 首次登记当前 entryId/senseId/exampleId，将它们作为现有对象的稳定标识，保留 M2 引用。中文 sidecar 的 target 使用同一组 ID。
2. 登记源定位、已存在的 source senseid、完整英文与 SHA-256 语义上下文指纹；**身份与内容修订分开**。不能只换成另一个包含数组索引的哈希。
3. 初期冻结英文快照，不运行 `data:refresh` 来补中文。日后刷新先比对源 ID + 词头 + 词性 + 上下文，唯一且一致才复用身份；重排本身不换 ID。
4. 新内容分配持久身份；歧义、合并、拆分或找不到对应对象进入待审核迁移表，保留旧 ID 别名与孤立记录，不自动按同拼写吸附。
5. 英文内容改变使旧译文进入 needs_review，并保留旧版本。M3.1 不发生这一修改，也不触发 210 个音频路径变化；未来真正英文改动需单独音频增量方案。

### 6.3 中文记录建议字段

| 字段 | 约束 |
| --- | --- |
| id / revision / schemaVersion | 翻译记录身份、递增修订、结构版本 |
| targetKind / entryId / senseId / exampleId | sense 或 example；例句必须同时带所属 senseId；词性不能仅由词头猜测 |
| englishText / context | 原英文；词头、词性、完整释义链、标签、例句上下文；不能由生成结果改写目标 |
| sourceSnapshotSha256 / sourceFingerprint | 绑定来源版本和特定对象内容，检测陈旧翻译与错误挂接 |
| locale / chineseText | 中文语言标识；缺失为 null，不能用空字符串冒充成功 |
| status | source_verified / human_reviewed / ai_draft / needs_review / unavailable |
| origin / sourceRefs | source / ai / human；固定源 URL、许可、署名、原始文件哈希和真实 JSON 定位；无外部来源的人工内容不伪造链接 |
| generator | provider、model、promptVersion、生成时间、任务 ID；非 AI 可为空；不含密钥 |
| review | 审核人/时间/结论/问题；AI 自检不等于 human_reviewed |
| publication / updatedAt / reason | draft 或 released，更新时间；缺失/冲突/过期的可解释原因 |

第一步建立 **208 个中文目标状态**（113 + 95）：现有 3 个经来源重新核对后 source_verified，其余 205 个 unavailable。状态覆盖 100% 不等于翻译完成 100%，质量报告分别显示这两个比例。

需要保留多个候选及修订历史，选中记录不覆盖其他来源。用户纠正 source_verified 中文时新增人工修订，不篡改原始源行。

### 6.4 来源分层与准确性规则

1. **现有来源**：保留三条精确匹配中文；复核 29 条未匹配候选。可用精确匹配和候选检索帮助审核，但模型不能把疑似映射直接提升为 source_verified。
2. **有授权的双语数据**：逐项登记许可及出处，先评估有限词条覆盖。CC-CEDICT 官方提供可下载的中英词典及 CC BY-SA 4.0 说明，但其结构不是本项目 Wiktionary 义项/例句对齐表；建议仅作候选词语参考，不能反向词头检索后自动灌入所有义项。本轮未下载或接入新词库。[官方来源](https://www.mdbg.net/chinese/dictionary?page=cc-cedict)
3. **AI 草稿**：给出明确目标 ID、词性、完整上下文，只允许返回目标 ID 和中文/疑问，不允许模型生成来源名、URL、许可、审核人；这些元数据由工具固定。JSON schema 校验只能验证结构，不能证明翻译正确。
4. **人工补充/审核**：可独立修订或批准草稿；有歧义时标 needs_review，不能强行发布。始终保留英文、中文原文与修订追踪。

中文来源的许可与代码许可分别维护；本次不抓取商业词典或受保护内容。现有中文繁简写法原样保留；新增草稿的用字偏好应可配置，不以自动转换代替语义审核。

### 6.5 独立工具流程

建议后续新增 `scripts/chinese-content.ts` 与提供商适配接口；下面是拟定能力，**目前没有这些命令**：

| 动作 | 行为和验收点 |
| --- | --- |
| scan / plan | 扫描 208 个目标，输出缺失、重复、候选、孤立/陈旧映射和成本估算；默认 dry-run，不发请求 |
| generate | 先已有来源、再缺失草稿；预算/任务上限/输出长度、低并发、可重试错误有限退避；首次小批检查后再扩到计划范围 |
| resume | 稳定任务键与原子写入；成功不重复请求；每次尝试记费用预留；未知中断结果单列，不能保证外部 API 恰好计费一次 |
| regenerate --id | 只处理指定目标，旧审核版保留；新草稿不能覆盖旧正式内容 |
| import-review / validate | 检查所有引用、英文指纹、状态转换、合法来源、重复和修订冲突；失败不改正式文件 |
| publish | 只将符合发布策略的记录写入中文 sidecar，校验完整状态覆盖和 M2 哈希，再构建/部署 |

任务键建议涵盖 targetKind、目标 ID、父 senseId、英文/上下文指纹、中文语言、提供商/模型及提示版本。内容相同但义项不同保留独立映射；只有上下文确实相同的任务才能共享结果并保留别名。重新排序、重新打开页面不产生付费请求。

成本预览按选定提供商的输入/输出 token 单价、实际上下文和输出上限计算，包含重试预留，运行中累计已提交估算与服务响应 usage。当前所有释义/解释约 6,181 个 JS 字符、例句 4,375 个 JS 字符，**不是 token 数或完整提示总量**；不能按 M2 Polly 的字符价格估算 LLM。供应商、模型和预算尚未确定，本轮不报虚假的美元金额，不把已有 AWS Polly 身份视作已获翻译服务权限。

没有凭据时仍可完成扫描、状态迁移、候选匹配、人工编辑、导入导出与来源追踪；生成器明确返回未配置，不能填假中文或把模拟接口成功记为真实生成。

### 6.6 审核页与正式页面

- 建议 `#/content-review`，按词头、词性、义项、目标类型与状态筛选；并排显示英语、对应例句、原译文、候选来源和指纹；编辑、保存、批准、标错、撤销和导出。
- M3.1 需要最小审核持久化，建议先引入共享 IndexedDB 基础及审核/修订/备份表，M3.2 再扩展个人词汇表；这不提前开发收藏功能。
- 当前是无后台的静态网站。审核页的保存只能写**本机数据库**；导出审核包后，由本地工具验证、写中文 sidecar 并发布，才能让其他设备得到正式内容。UI 分别说明“已保存到本机”和“已发布版本”，不能假装浏览器直接写服务器文件。
- 隐藏入口不是鉴权。该页不保存密钥、不提供服务器写权限；其他访问者只能改变自己的本机副本。后续若提供在线共享发布，须单独鉴权方案。
- 建议默认正式详情只使用 released 的 source_verified / human_reviewed 版本；ai_draft 保存在审核页。若用户希望在详情页预览草稿，提供明确的草稿预览开关，展开后标注“AI 辅助翻译 · 待审核”，仍不能把它作为正式发布。这解决任务书“审核后写正式数据”与“草稿有标识”两项要求；请在方案确认时确定展示偏好。
- 缺失提示改为“暂无可靠中文释义，待补充”/“暂无可靠中文译文，待补充”；不再将源数据内部缺失说明直接展示。英英优先、逐条折叠和导航后重置继续保留。

## 7. 个人数据与安全迁移设计

### 7.1 本地数据库分期设计（建议）

建议采用 IndexedDB，共享 Repository 层，不让组件直接操作散落的 localStorage。可评估 Dexie 的事务和版本升级支持，具体版本须安装前锁定并完成 WebKit 小型验证，本轮未安装。参考 [Dexie 升级接口](https://dexie.org/docs/Version/Version.upgrade())、[事务设计](https://dexie.org/docs/Tutorial/Design)、[许可](https://github.com/dexie/Dexie.js/blob/master/LICENSE)。

| 引入阶段 | 表/对象 | 主要字段与约束 |
| --- | --- | --- |
| M3.1 / DB v1 | meta、contentReviews、contentRevisions、backups | schemaVersion、dictionaryVersion、数据修订号；目标+修订唯一；发布状态和本机状态分离 |
| M3.2 / DB v2 | vocabulary | entryId 主键；favorite/favoritedAt 独立于 learningStatus；joinedAt/updatedAt；暂停前状态；不复制整个词典 |
| M3.3 / DB v3 | reviewCards、studyEvents | entryId 唯一卡片、FSRS 状态/版本/参数、dueAt；事件 ID/幂等提交 ID、UTC 时间、学习日期/时区、before/after 与评分 |
| M3.4 / DB v4 | articles、articleAudio | 文章 ID/revision、目标 entryId/可选 senseId、正文/翻译/生成来源、覆盖位置；按文章版本与音色标识音频 |

这些 DB 版本是规划编号，实施时统一维护迁移注册表。词典版本、数据库结构版本、中文内容修订、备份格式版本、FSRS 库版本和算法版本必须分别记录，不能共用一个 M3 字符串。

现有 `dictionary.audio-settings.v1` 继续由现有设置模块读写，不迁移成第二份有效音色状态。备份可携带经过白名单验证的音色/速度快照；导入时显式恢复，失败须说明，不能假装 localStorage 与 IndexedDB 可跨介质原子提交。

### 7.2 状态语义

- 收藏布尔值与 new/learning/review/mastered/skipped 独立；取消收藏不删除学习历史。
- 查询事件可记录，但不自动收藏、不创建已掌握状态、不作为成功复习。M3.3 开始记录后才有真实事件，不从 M2 浏览历史虚构过去的学习。
- 单词与独立短语都使用 entryId；词形归词元，派生词保持独立。
- 手动 mastered 记录显式事件，保留 FSRS 卡片并暂停排队，不伪造 Easy；skipped 同样保留原卡片和暂停前状态。恢复时以真实旧状态和当前时间重新进入规则，不清空复习历史。
- 初次复习仍遵守原产品流程：先英文条目，提示是英文例句；提示后服务层也限制评分不高于 Hard，不能只隐藏按钮。中文和答案另行展开。

### 7.3 迁移与恢复流程

1. 启动先识别数据库/内容版本；高于当前应用支持的版本只进入保护/导出模式，不强开、不清空。
2. 对现有库取得一致快照，验证 ID/引用/计数，记录校验值、旧版本和时间，先提交到既有 backups 表；同时提供下载到 Files 的 JSON。初次建库没有个人旧数据，不把不存在的数据写作“迁移成功”。
3. 多标签页进入迁移协调状态；每次写入检查修订/迁移标记。versionchange 关闭旧连接，blocked 给出关闭旧页面提示，不删除数据库解除阻塞。
4. 版本升级事务内执行确定性变换与结果验证，事务中不调用网络或 LLM。失败中止升级，保留旧库与已提交备份；成功后记录新版本、迁移 ID 和校验结果。
5. 回退不能简单调低 IndexedDB version。旧快照先经兼容转换，在受支持结构中事务恢复；无法安全转换时保留现库和原备份、进入恢复模式，绝不先清库再尝试。
6. 测试断电/关页、配额不足、损坏 JSON、未知字段/版本、重复导入、孤立 entryId、两个页面竞争和部分写入；任何失败不得以静默重置解决。

首次 M3.1 只增加中文/审核结构，当前英文和音频的上述哈希必须不变。字典未来删除/改 ID 时保留个人记录为待重新关联，不自动归到同拼写的新义项。

### 7.4 JSON 备份格式与跨设备边界

建议备份包含 format/schemaVersion、appVersion、dictionaryVersion、createdAt、timezone、各表记录数、payload 和 SHA-256 校验。校验用于发现损坏，不是数字签名。导入先做大小限制、schema/枚举/时间与引用校验，显示冲突/未知条目和合并或替换预览，再一次事务提交；保留导入前备份。未知词条进入隔离待映射区，不被丢弃或自动合并。

JSON 备份必须包含中文人工修订、词汇状态、完整学习日志和文章；文章音频若只保存 URL，应明确“备份不含 MP3”。本地导入音频可提供单独媒体包和校验清单，不能导出不可跨设备恢复的 blob URL。

浏览器数据按 origin 隔离，稳定生产域名与 `b92bfee6...`/旧 `651e2c06...` 快照不能直接共享存储。M3 以稳定生产入口为长期使用地址；跨设备/不同站点通过导出导入迁移，不承诺自动同步。

IndexedDB 有配额和被清理风险；可按能力调用 StorageManager 持久存储申请并显示结果，但不能保证永不丢失。浏览器重启、Safari 和独立 PWA 必须分别实测，外部备份不能只留在同一份可被清除的浏览器存储中。[WebKit 官方存储策略](https://webkit.org/blog/14403/updates-to-storage-policy/)

### M3.2 个人词汇管理

实现 vocabulary 表与迁移 → 收藏/取消 → mastered/skipped/恢复 → 列表检索与时间排序 → 批量操作 → 备份恢复。空状态明确；批量变更使用事务并可恢复。验收覆盖单词/短语、刷新/重开、收藏与学习状态独立、取消收藏不删复习历史、导入失败不损坏已有数据。

### M3.3 学习事件与 FSRS

先固定事件语义、时区/学习日边界和重复提交 ID，再接调度库；评分、卡片更新和学习事件同一事务提交。new 卡片按实际开始学习创建，到期复习优先，mastered/skipped 排除；恢复不重造历史。统计从实际事件计算，同一天重复查看不能计作多个已掌握词。

候选 **ts-fsrs**：官方 TypeScript 项目，MIT；当前主分支说明 v6 需要 Node >=24，默认 FSRS-7，并明确库版本与模型版本不同。此为选型证据，不是已经安装或锁定了发布版；实施前验证实际 npm 版本、Vite 浏览器包/资源加载和 WebKit，避免误把 Node 优化器带进 PWA。初期不训练个性化参数，持久化确切库/算法版本、参数与卡片状态。[官方仓库](https://github.com/open-spaced-repetition/ts-fsrs)、[许可](https://github.com/open-spaced-repetition/ts-fsrs/blob/main/LICENSE)

验收用固定时钟测试四种评分、提示限制、重复提交、due 队列、跨日/时区变化、手动掌握/恢复以及事件一致性。建议事件存 UTC 时间 + 操作时 IANA 时区和 localDate；学习日边界作为显式设置，初值在本模块确认，不硬编码服务器时区。进入学习页面不等于完成学习。

### M3.4 每日阅读

分为词汇筛选与文章模型 → 安全生成适配 → 覆盖验证 → 历史/中文折叠 → 动态音频与缓存。输入保存生成当时的目标 entryId/可选 senseId 及词形，默认 150–300 英语单词，长度可调。仅查询词汇不算已学；手动 mastered 可作为用户选择的已知词汇，不伪造其学习事件。

覆盖由确定性分词/已知词形与短语匹配计算，记录文章版本、实际 surface 和明确坐标单位的起止位置；不把 make 算在无关子串里，也不使用模型自报百分比。报告未覆盖词；文本命中仍不等于义项使用正确，需内容质量检查。文章翻译与生成来源独立，修改正文会使旧覆盖结果、中文和音频陈旧。

| 方案 | 优点 | 代价/未满足部分 |
| --- | --- | --- |
| B：受控本地生成，导入文章/音频包 | 复用现有安全本地身份和审计方式，无新付费云设施；适合先验证质量/缓存 | 手机不能独立一键在线生成；这是过渡流程，不能据此宣称最终一键阅读目标完成 |
| A：受鉴权保护的云端生成 + Lambda/Polly/S3 缓存 | 可支持 iPhone 独立请求与长期音频 URL | 需要额外模型服务、受保护 API/鉴权、执行角色、存储、日志与预算；Lambda+Polly 本身不会生成文章正文 |

**建议先做与部署方式无关的选择/文章/覆盖/历史接口；若接受本地过渡则先 B，最终手机一键目标需确认 A 或等效受控服务。** 选择 A 前另交请求/存储/流量/日志成本测算、鉴权、最小权限、请求长度/频次/每日总额和删除策略，不擅自创建服务。没有账号不等于可以把付费 API 公开，不能以 CORS 充当鉴权。

文章合成沿用 en-US、Neural、Joanna/Stephen 与既有调速原则，缓存键包含文章英文哈希、修订、音色、引擎与发音规则，按需生成。新增独立文章音频目录和 manifest，不写入现有 210 清单；文章资源类型与 AudioPlayer 适配须先做兼容评审，不能将文章伪装成旧词条或重写稳定播放器。现有 source/license 记录继续保留；新正文来源不得伪称 Wiktionary。

验收包含真实模型输出和失败、中断重试、目标覆盖、保存删除、刷新恢复、音频身份/缓存/错误反馈与两音色。仅有示例文章或离线模板不能视为 AI 阅读生成通过。
