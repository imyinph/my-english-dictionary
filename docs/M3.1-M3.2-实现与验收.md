## 3. 新中文数据结构

三个文件角色分开：

| 层 | 文件 | 用途 |
| --- | --- | --- |
| 既有不可变迁移 | `public/data/content-v1/` | 保留 r1、英文上下文/来源与 208 个历史目标；本次字节不变 |
| 中文编辑历史 v2 | `content/zh-senses-v2.json` | 113 个义项实体，当前修订选择，原始记录与审核后的新记录并存；不随 public 发布 |
| 精简正式数据 | `public/data/chinese-senses.json` | 113 个状态；只携带获批准且许可明确的简释/解释/署名，其他目标无候选正文 |

实体结构：

| 字段 | 含义 |
| --- | --- |
| id / senseId / entryId / version | 稳定义项 ID、父词条和内容修订，不用词头或数组下标作为连接键 |
| locale | zh-Hans |
| englishText / partOfSpeech / sourceFingerprint | 对应冻结英文义项与完整上下文指纹，检测错挂和陈旧内容 |
| glosses / explanation | 多个独立简释字符串；扩展解释为字符串或 null，缺失不伪造 |
| source | dictionary/human/ai、名称、源记录 ID、源数据版本、许可状态、许可、署名、URL、规范化说明 |
| matching | 方法、confidence（允许 null，不虚构正确概率）、证据 |
| review | pending/approved/rejected、审核人、时间、审核包指纹 |
| translationStatus | missing/candidate/complete，complete 必须 approved 且许可允许发布 |
| createdAt / updatedAt | 初始迁移日期保留，真实审核操作记录实际时间 |

bundle 的 schemaVersion=2、revision 与字典 SHA-256 分开；M2 音频 schema 不变。历史采用追加修订，currentRecordIds 指向当前版本。本次 113 条初始记录加 3 条审核后修订，共 116 条历史记录。

初始 source_verified 不直接当作 approved。用户确认对应的具体简释后，本地审核导入器校验 senseId、版本、指纹、简释和解释一致才追加批准；重复导入同审核包无新增记录，过期版本拒绝。构建还核对原审核包，编辑译文后不能继续沿用旧批准。

未来供应商可在来源适配和候选层扩展，UI 契约不依赖 ECDICT。当前迁移审核路径仅批准/拒绝已有来源候选，不提供任意改写源出处或更改许可的后门；新供应商正式准入、解释编辑及完整修订流程属于后续增量。

## 4. 导入和匹配流程

`scripts/import_ecdict.py` 使用 Python 标准库。CSV 支持引号、逗号、真实换行和字面 `\\n`；词头规范大小写/空白，不擅自合并短语与带连字符词。词性从明确的释义标记获取；频率 pos 字段保留原样，不凭频率或猜测赋予中文词性。

按规范化词头、英文定义组与中文组去重，重复源位置仍保留。异常列数、空词头、英文/中文/词性缺失均统计；仅索引当前十词。原 CSV 完整留存，规范化对象保留 raw 和源数据行号、逐记录哈希。自定义 CSV 可用同一接口导入，不覆盖英文数据。

`scripts/ecdictMatching.ts` 先词头，再分别取同词性英文/中文组，比较英文定义词项与可审计概念规则，用例句和语域辅助。其局限、门槛、原理和 113 个结果详见质量报告。没有模型调用，分数不是语义正确概率；源英文与中文没有配对键，始终保存 `bilingualAlignment=unverified`。

本地 `artifacts/ecdict/index.json` 是词头 → 源记录 ID 索引及原文；`matches.json` 包含上下文和证据。可提交的 `content/ecdict-match-summary.json` 仅含本项目英文、状态、源定位与分数，不含 ECDICT 原定义/中文正文。发布时只把候选存在这一状态带入未补全目标，绝不把中文上下文组当正式释义。

## 7. 本地运行与复现

正常使用只需 Node 24 与既有 pnpm；Python 3 用于导入和 CSV 测试。当前环境已安装，无需新增翻译服务凭据。

```powershell
# 运行前请确认 PATH 上的 node 为项目要求的 Node.js 24。
pnpm install --frozen-lockfile
pnpm dev
```

访问 `http://localhost:5173/#/entry/creation`：英文先显示，“创作品”直接显示；中文来源默认折叠；扩展解释如实标缺失。creator/make 仅对应义项显示另两条简释。creatively 显示待审核；make sense 的四个义项仍无可靠中文。

ECDICT 流程：

```powershell
pnpm ecdict:import --fetch
pnpm ecdict:match
pnpm ecdict:verify
pnpm ecdict:report
pnpm zh:publish
```

首次 fetch 下载固定 66 MB CSV 与许可文件；再次默认 import 使用本地缓存并核验固定 Git blob。不下载 stardict.7z。自定义数据：`pnpm ecdict:import --input C:/path/ecdict.csv --dataset-version 自定义版本`，仍只处理当前十词。自定义结果须重新审查，不能把其许可自动升级为已核清。

审核/发布：

```powershell
pnpm zh:migrate
pnpm zh:review-template
# 查看 artifacts/chinese-review-template.json，填审核人、真实时间和逐项决定。
# 只审核已有候选的准确文本；不能通过改文本同时保留旧批准。
pnpm zh:review --file C:/path/review.json
pnpm zh:publish
pnpm zh:verify
```

当前三条已批准，新的模板没有未审源候选属于正常情况。ECDICT 候选在单独本地报告中，许可未核清前不能通过本流程发布。发布只写本地静态 JSON，**不是上传 Cloudflare**。

验证命令：

```powershell
pnpm test
pnpm release:build
pnpm test:e2e
pnpm audio:verify-media
```

发布文件约 55.7 KB，只在进入详情时加载一次并内存缓存，失败可重试；使用 no-cache/must-revalidate 响应头。首页无需先下载中文；也不下载 ECDICT 索引。中文失败不阻断英语、搜索、导航或播放。无新增 service worker，不承诺离线。

## 8. 迁移与回滚

实施前备份：`artifacts/source-backups/before-m3-chinese-ecdict-20261114-131032.zip`。本地仍无 Git 提交基线，不使用 git reset/restore 代替可靠恢复。

v2 使用新文件，不覆盖 content-v1。migrate 已存在时校验并保留审核；首次迁移若发现 v1 已有后续修订，会要求显式迁移，不能静默丢弃。未知结构/损坏历史直接失败。修改审核历史或发布文件前，旧文件按 SHA-256 备份到 `artifacts/content-backups/`；同审核包重复导入无写入。审核证据先落盘，后原子替换历史；中断最多留下未使用证据包，不产生无出处批准。发布前先生成并校验完整内容，再原子替换。
