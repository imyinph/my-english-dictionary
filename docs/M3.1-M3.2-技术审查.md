# M3.1 / M3.2 新任务技术审查

日期：2026-11-14。依据：用户最新《M3.1 + M3.2》任务书，替代旧阶段编号：本次 M3.2 是 ECDICT 导入，不是收藏功能；后续 M3.3 指 AI 补全，不是本次开发范围。

## 修改前结论

- React 19 / Vite 8 / TypeScript 5.9，Node 24，静态 Cloudflare Pages，hash 路由，无 service worker。英语 JSON 异步按需加载并在内存复用；失败清除 Promise 可重试。无个人数据库。
- `kaikki-subset.json` schema 1：17 源记录合并为 10 词条；词性在 sense 层；113 个 sense、95 个例句。每个例句带 exampleId 和所属 senseId，不按单词共用翻译。
- 上一增量 `content-v1` 登记了 208 个稳定目标并冻结 M2 ID；源 adapter 的旧 ID 仍含位置索引，必须保持快照冻结，不能直接刷新源词典。构建校验英文和音频哈希。
- 当前只有 3 条源中文（creation、creator、make）。其余源中文多为记录级、英文 sense 描述与本项目 gloss 不完全对应；例句源中没有中文。UI 缺失提示是内容覆盖不足的结果，替换提示不能补齐数据。
- `App.tsx` 直接读取 `sense.translation` 并调用通用 `Translation` 折叠组件。新独立中文文件尚未接入 UI。需把中文简释/解释放在独立语言组件，例句译文继续单独折叠。
- 最新批准行为是“中文简释默认显示、扩展解释折叠、只有已审核内容正式展示”，覆盖旧的全部中文折叠规则。旧 source_verified 表示来源可核对，不能自动提升成人工 approved。
- M2 实际固定 en-US、Joanna/Stephen、ap-southeast-2；音频 210 条。任务背景提及 UK，但当前稳定版没有 UK 正式音频切换，本次不新增或改造音频功能。
- 当前回归基线是 67 单元（含原 51）和 81 浏览器测试，使用生产构建及桌面/移动 Chromium、移动 WebKit；这不等同于 iPhone 真机验收。

## 调整方案与涉及文件

1. 保留 content-v1 与原始中文历史；增加 `content-v2` 义项实体，glosses 数组、explanation、来源、匹配方法、置信依据、pending/approved/rejected 和 missing/candidate/complete，审核与许可分开。初始迁移只产生 pending 来源候选或 missing，不伪造审核。
2. `src/domain` 定义契约，`src/providers` 校验并缓存发布数据；`src/components/SenseTranslation.tsx` 独立展示，`App.tsx` 只组合。英文加载不因中文文件失败而中断。
3. `scripts` 增加可重复迁移/审核导入/发布、ECDICT 流式下载/CSV 清洗与有限索引、离线候选匹配。源文件保存在忽略的本地目录，客户端不进行大规模匹配。
4. 匹配先词头、再词性，再英文语义线索及原义项完整上下文/例句；报告证据与歧义。无双语对齐证据时不能按行号关联，也不能把整行中文分发给所有 sense。
5. 正式静态文件只包含发布许可明确且 approved 的中文；候选与逐义项报告留在本地，所有 113 个义项保留状态，包括专业/罕见义项，不删减范围。
6. 增加模型、状态、迁移幂等、CSV/去重、跨词性/多义项错误匹配测试；调整旧折叠断言为最新产品行为，保留导航/例句/音频断言。

## 迁移风险与实施顺序

先备份上一增量源码；新目录迁移，不覆盖 content-v1、词典、音频清单或媒体。迁移重复运行验证并保留已有审核；失败不清空。旧的 3 条源中文并未人工审核，因此初始正式展示可能暂时减少，必须提供实际审核入口，不能自动改为 approved 来维持表面覆盖率。

依序完成模型与受控本地审核/发布 → 中文组件 → ECDICT 真实导入与候选报告 → 单元、类型、构建、浏览器和 M2 回归 → 文档及部署步骤。无需为普通实现选择再次等待确认；不做 AI 内容生成、不开发收藏/FSRS、不扩大词库、不重新合成音频。
