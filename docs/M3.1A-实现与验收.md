## 3. 身份、匹配与来源规则

身份保留现有 ID；SHA-256 内容指纹独立于身份。指纹包含目标类型、英文文本、词头、词性、完整 gloss 链、用法标签、所属义项例句、存在的原始 senseid/id 和显式词源号，不包含数组位置或旧 ID。例句绑定父义项上下文，同一句英文不能跨义项复用身份。

`planIdentityReconciliation` 仅输出候选迁移计划：唯一完整上下文一致才可保留旧身份；内容改变、未找到或多重匹配进入 unresolved，旧对象保留为 orphaned。它不写入新 ID，也不更改原始词典或音频。在内存中反转源记录/义项顺序，均成功映射回全部 208 个旧 ID。

**尚未实现上游换版的自动发布迁移。** 实际生产仍冻结英文快照；未来更新需要受控导入、人工消歧与中文/音频影响检查。不能只修改基线哈希让构建放行。

每个引用保存 snapshotPath、快照 SHA-256、JSON Pointer、词典 URL、提取 URL/原文件 SHA-256、许可与署名。JSON Pointer 仅在其快照哈希下有效。源候选还列出英文 sense 描述、词性、精确匹配目标及同源记录中的上下文目标；后者是人工查看范围，**不是已经批准的语义匹配**。

中文仍只采用原 adapter 的精确映射，保留义项级来源优先于记录级来源。若同一源行精确命中多个义项，进入 needs_review，不自动发布。本批实际没有这种多重匹配，测试使用明确的夹具验证该分支。

## 4. 状态、审核和历史校验

- 目标种类、entryId、senseId、exampleId、英文、上下文、指纹与快照版本必须一致；孤立、跨义项、陈旧引用直接拒绝。
- 缺失中文为 null + unavailable，并有 reason。空字符串不能代表完成。
- ai_draft 必须保留 provider/model/promptVersion/jobId/generatedAt，不能带伪造词典中文来源；未审核记录不得 released。
- human_reviewed 必须有具名审核记录和 approved；AI 草稿被人工确认后仍保留 AI origin/generator。
- 只有 source_verified 或 human_reviewed 才允许 released。审核被拒绝必须为 needs_review。
- r1 迁移记录不可改写或丢弃；后续通过新修订和 currentRecordIds 选择当前版本。修订连续、不能倒退时间或遗漏对象状态。
- `validateContentUpdate(previous, proposed, inventory)` 供下一增量的编辑/导入工具使用，检查所有既有修订原样保留、bundle 修订恰好递增。重复输入不新增修订。
- 静态格式校验不能证明有人真的审核过译文，也不是数字签名。批准动作、修订持久化和导出/导入由 1B/1C 实现，不能凭 JSON 结构通过声称语义已审核。

第一版只认可本快照中可复核的三条源中文；其他双语来源尚未接入。新来源必须另行登记授权和适配规则，不能通过填入任意 URL 绕过校验。

`initialMigrationAt` 采用任务日期、日粒度（配置标明 timestampPrecision=day），不是精确用户操作时间。未来人工操作和生成时间应记录实际时间，不能沿用初始日期。

## 5. 运行和验收步骤

使用 Node 24 与项目 pnpm，在项目根目录执行。本机 PowerShell 如默认 Node 26，先切换：

```powershell
# 运行前请确认 PATH 上的 node 为项目要求的 Node.js 24。
pnpm content:scan
pnpm content:scan --report
pnpm content:verify
```

预期：208 状态、3 可靠中文、205 缺失，33 源候选，其中 29 未匹配。默认 scan 不写文件或请求服务；带 `--report` 只写以下可再生报告：

- `artifacts/m3-1a-content-scan.json`：完整缺失目标清单、状态与候选统计。
- `artifacts/m3-1a-source-candidates.json`：33 行来源定位、匹配状态与查看范围。

首次环境迁移命令为 `pnpm content:init`，已在当前项目执行。重复执行仅校验现有文件，不覆盖任何后续修订，也不重新翻译。目标目录损坏或只有部分文件时明确报错，不静默重置。

完整验证：

```powershell
pnpm test
pnpm release:build
pnpm test:e2e
```

人工检查：

1. 查看中文 JSON 中 creation、creator、make 的三个 source_verified 记录；按 sourceRefs 的 JSON Pointer 在冻结源文件核对原文字面值、源 sense 和许可。
2. 查看 create 和任意例句：中文应为 null、unavailable、有原因；不能以状态登记成功认为译文已补全。
3. 查看候选清单中的 29 个 unmatched：它们没有被加入已发布中文。
4. `pnpm dev` 打开词典；搜索 creation、make sense，检查中文默认折叠、短语独立页与返回。页面内容与 M2 一致是本增量预期，友好缺失提示和审核页尚在 1C。
5. 选择 Joanna/Stephen、不同速度播放单词/短语/例句，确认仍使用现有 MP3。
