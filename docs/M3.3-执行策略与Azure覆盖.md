## 重试与暂停

Gemini 模型固定 `gemini-3-flash-preview`，配置模板及默认值已更新；显式配置 2.5 Flash 会在联网前拒绝。旧 404 日志保留。

HTTP 429 / 5xx 优先使用服务器 `Retry-After`（秒数或 HTTP 日期）及响应 JSON 中 `retryDelay`（包括 google.rpc.RetryInfo、秒/纳秒 Duration）。多个有效值取最长值，避免早于服务器要求重试。

无有效服务器等待时间时使用 `min(600000, 30000 × 2^重试序号 × (1 + 0.25 × 随机数))` 毫秒。六个等待基准为 30、60、120、240、480、600 秒，最大 10 分钟。已有 RPM 保护仍可延长过短的服务器等待。内部每段等待不超过 60 秒。

初次请求之后最多连续重试 6 次（总计 7 次）；同一请求的历史尝试计数保留，重启不重置。原有字符、Token、请求总额保护继续有效，可能更早停止。401/403/404 不自动重试；不确定网络错误停止。

服务器要求超过 10 分钟时，直接暂停并保存 `notBefore`，不会截短到 10 分钟后提前请求。重试耗尽写入持久 `geminiPause`；换请求或重启都不会自动绕过。恢复需后续明确操作，不自动清除暂停。

缓存哈希算法保持兼容，旧缓存文件没有改写。实际 Gemini API 版本在新日志中明确为 v1；历史哈希字段中共用的 Azure 3.0 值保留，仅为了缓存兼容。

生成后先做本地确定性检查：ID/POS/原文一致性、中文结构、源外信息风险、重复简释、模型明确的不确定性以及仍适用于同一候选文本的历史冲突。

只有具备有效结构和 Azure 结果、且存在实质风险/冲突的候选进入一次 Gemini recheck。取消对所有候选的无条件 compare，也取消 recheck 后再次 compare 的调用链。已有复核结果不重复调用。

字符串相似或本地规则通过不能证明语义正确。没有实质风险但缺少有效语义审核证据的条目保留 needs_review；复核修订后也保留 needs_review，附原文、修订与本地检查依据，不把同一模型自检视为独立批准。已有通过检查的内容和用户批准内容不被这次 Azure 阶段重算。
