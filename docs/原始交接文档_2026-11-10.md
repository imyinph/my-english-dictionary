# 英语词典 App｜Codex 开发交接文档

> 版本：需求交接 v1.0  
> 更新日期：2026-11-10  
> 项目阶段：产品需求讨论已进行一轮；**尚未确认已有代码仓库、框架或部署环境**。  
> 本文件用于在 Codex 中继续设计和分阶段开发。**明确区分“用户已确认”与“开发建议/待验证”，不得把后者视为已定需求。**

## 1. 项目目标与产品原则

开发一款**仅供个人使用**的英语词典 + 单词学习 / 复习 Web App，优先在 iPhone 上获得接近原生 App 的使用体验，同时能在 Windows 浏览器使用并**自动同步学习进度**。

核心原则：

1. **英英优先，中文辅助**：英文释义始终优先展示，中文释义和例句中文翻译默认隐藏，只有主动点击才显示；促进英语思维。
2. **查词、理解、发音、学习、复习一体化**：词条、短语、词族、真实语境视频相互连通。
3. **真实语境**：希望把 YouGlish 式的母语者视频用法嵌入**单词/短语详情页内部**，而非默认跳转到其他页面。
4. **主动回忆与间隔重复**：以 FSRS 为复习调度框架，允许用户主观跳过已经很熟悉的单词。
5. **简洁、低维护、优先免费**：可以接受合理小额支出，但方便、稳定优先于极致省钱。
6. **无需 App 内 AI 问答/生成朗读文章**：用户会在 ChatGPT 中另建口语项目；App 只负责一键导出所学词汇。

## 2. 已确认的词典功能

### 2.1 单词详情页

- 默认优先提供**简洁、学习者友好的英文释义**，结合“简明解释 + 完整英文句子解释”的风格（用户选择牛津学习词典与柯林斯风格结合）。这是一种**呈现风格**，不代表可以复制商业词典的专有内容。
- 按**词性和不同义项**分组，每个义项分别展示英文释义、典型例句与相关词汇；避免将不同义项的近/反义词混在一起。
- 每个义项期望 **2–4 条英文例句**，尽量由简单到复杂；高亮目标词或短语。
- **中文释义和例句译文默认折叠**，独立点击后展示；跳到另一词条时仍默认隐藏。
- 例句里的单词也能点击查询；提供返回原词条能力。
- 支持单词收藏 / 加入学习；**仅查询不会自动进入复习系统**。

### 2.2 词汇关联网络（重要）

词条必须包含三个独立模块：

1. **Synonyms / Antonyms**：近义词与反义词，尽量按义项组织；必要时体现语义差异。
2. **Word Family**：派生词，例如 create → creation / creator / creative / creatively / creativity；包括名词、动词、形容词、副词等。
3. **Word Forms**：屈折变化，例如动词过去式、过去分词、现在分词，名词复数，形容词比较级/最高级等。

**所有关联词可点击进入各自词典详情页**，支持后退，构成可导航的词汇网络。派生词和语法变形必须分开展示；语法变形可解析回词元（lemma），但也要让用户看见原变形。

### 2.3 短语与固定搭配

- 查询单词时，在其详情页**直接列出相关常见短语和搭配**。
- 点击某短语可进入**独立短语详情页**，有自己的英文释义、例句、隐藏的中文辅助释义、发音、YouGlish 视频、收藏、加入学习、FSRS 复习、标记已掌握和导出能力。
- 短语和单词在学习系统中是**同等地位的学习条目**，不要把短语只是当作单词页面上的静态注释。
- 短语详情中的关键词可以继续点进单词页。

### 2.4 搜索与查询历史

- 支持直接搜索单词及短语，建议实现输入联想、拼写纠错和单词变形识别（这三项是已提出并未被否决的功能方向；可分阶段实现）。
- 自动记录查询词条及时间；支持按日期查看、搜索历史、清空历史。
- 查询历史与学习词库**彼此独立**；用户可从历史记录**批量选择加入学习**。

### 2.5 朗读与口音

- **全局默认美音（US）**：单词、短语、例句、YouGlish 口音筛选尽可能一致。
- 用户可以在设置中手动切换**英音（UK）**，全 App 生效。
- 单词/短语可以点击发音；例句可以播放整句朗读；支持慢速/可调速播放。
- 发音可采用授权真人音频或合适的 TTS。**不能假设所有词条都存在真实录音，也不能把浏览器 TTS 说成真人录音**；缺少对应地区声音时应告知或安全降级。

### 2.6 YouGlish 真实语境视频（重要，但有授权风险）

目标体验：

- **内嵌在词条/短语详情页**，位于释义和例句附近；不是跳转到独立的视频页面。
- **按需加载**视频，避免首屏等待和流量浪费；支持视频切换、播放/暂停、调速等官方支持的能力。
- 美音默认优先，切换设置后优先使用英音视频。
- 若短语找不到完全匹配的视频，显示无结果状态与合理的外部查看入口，不伪造视频。
- 视频区域可折叠；优先保证查词本身流畅。

**开发门槛 / 法务注意：** YouGlish 官方提供网页嵌入 Widget 和 JS API，但官方开发政策写明：**在 mobile app 中使用 API / widget 应先联系官方取得明确许可**；PWA / iOS Web Clip 是否被视作此类用途，**不能自行推断已经获准**。正式集成前确认授权；不能擅自抓取 YouTube 内容或绕过播放限制。若未获许可，先做可替换的 VideoProvider 接口，并提供跳转 YouGlish 的合规备选。遵守 YouGlish、YouTube 的显示、署名、隐私和最小播放器尺寸要求。

官方资料：
- https://youglish.com/api/doc/widget
- https://youglish.com/api/doc/js-api

## 3. 已确认的学习与复习机制

### 3.1 新词来源：双轨制

1. **系统词库**：从词库中按计划学习（设想四六级、雅思、托福等；**具体可合法使用的词库及名单尚待选择**）。
2. **自主添加**：阅读或生活中查词后手动加入学习。

两种来源的单词和短语统一纳入同一套复习机制。相同词条应去重，不能重复创建互相冲突的学习卡；保留“来源/词库标签”。已经手动标记为熟练掌握的条目不再被推送为新词。

### 3.2 每日计划

- 每天新词数量**灵活调整**，不强制固定；建议默认目标为 **30 个/天**，但不是硬约束。
- 优先完成**到期复习**，再学习新词；允许当天多学或提前结束。
- 显示待复习数量、今日进度，可考虑估算学习耗时。
- 不设惩罚性打卡或欠账机制。

### 3.3 复习卡片的关键交互（严格遵循）

初始只显示：**英文单词/短语本身**（可有播放按钮，但**不要直接给出释义和例句**）。用户先独立回忆。

- **无需提示已想起**：查看英文答案后可评为「记得」或「简单」（可采用 FSRS Good / Easy）。
- **按“提示”按钮**：只显示**英文例句**，不展示中文释义。如果看了例句才想起来，最多评为**「不熟」**（FSRS Hard），不能再评为“记得/简单”。
- **看了提示仍想不起来**：评为**「忘记了」**（FSRS Again）。
- **未看提示就想不起来**：也允许直接评为“忘记了”。
- 每次评分后可展示完整英文释义；中文答案依旧需要单独点击才展开。
- 禁止点击提示后仍记录为高掌握度；应持久化本次评分、是否使用提示、复习时间等必要数据。

**FSRS**：用户接受 FSRS 间隔重复机制，建议初始目标保持率 **90%**，允许以后调整。不要用自制的固定 1/3/7 天计划冒充 FSRS。首次集成应按当前官方 API（包括版本兼容与 Node 运行时要求）实现并做测试。

官方参考：https://open-spaced-repetition.github.io/ts-fsrs/guide/quick-start

### 3.4 已熟练掌握（手动跳过）

- 新词学习和旧词复习时均提供 **“已熟练掌握”** 操作。
- 一旦标记，**退出日常新词推荐与复习队列**，不再强制复习。
- 可以随时手动恢复学习。
- 手动跳过与“经过 FSRS 多轮复习后掌握”应**分开记录、分开统计**；不得把手动熟词虚构成真实 FSRS 学习历史。
- **不做熟词抽查模式**（用户明确表示暂时不需要）。

## 4. 已确认的一键批量导出

目的：用户把当天学过的词汇复制进 ChatGPT 的另一个口语练习项目，由 ChatGPT 生成中长篇英语朗读材料。**App 不负责文章生成和 AI 聊天。**

功能：

- 导出**今天、最近 7 天、自定义日期范围**内学过的**单词 + 短语**。
- 默认纯文本列表、一键复制到剪贴板，适合直接粘贴给 ChatGPT；可额外提供 `.txt` 文件下载（建议）。
- **去重**：同一个词即使多次学习，导出列表只出现一次；保留短语的原始形式。
- 导出依据**学习活动**，不是“查询历史”。
- 后续可以选择附带英文释义；第一版以准确、干净的词条列表优先。
- 注意“学习日期”的定义：建议按用户本地时区、以**首次进入学习或当天发生有效学习活动**为条件；具体可在实现时明确说明并编写边界测试。

## 5. 多设备、安装方式与离线优先级

### 5.1 已确认

- iPhone 是主要场景，要像独立 App 一样从主屏幕打开、没有普通 Safari 地址栏。
- **PWA 是首选基础技术**：Safari 中“添加到主屏幕”，无需 App Store / 年度签名。
- 用户还喜欢通过 `.mobileconfig` 配置描述文件安装的**全屏 Web Clip** 体验；**保留为可选安装方式**，非必要第一优先级。
- iPhone / iPad / Windows 浏览器之间要有**账户级自动云同步**：学习记录、卡片状态、查询历史、设置、收藏等。
- 用户可接受少量花费，但优先方便可靠，尽量从免费服务起步；**暂时不必买独立域名**。
- 离线查询与离线复习曾被考虑，但用户后来明确表示**离线功能可以先不做**，因此属于后续增强项。

### 5.2 技术界限

- Web Clip / 描述文件本质是 Web 入口，并不自动产生原生能力；也不意味着能离线、能绕过 YouGlish 规则。
- 不应为了类似原生 App 的外观而要求用户安装来源不明或高权限的系统描述文件；最安全、最简单的主安装方法仍是 PWA。
- 云同步需要考虑登录认证、写入冲突、丢数据防护、导出备份。建议日常使用时本地缓存提升响应，但**不要承诺第一版完全离线可用**。
- 国内网络环境下应实测 iPhone / Windows 对部署平台、登录邮件、音频与 YouGlish 的访问情况。

## 6. 数据源与内容质量

先前讨论的候选来源：

| 来源 | 主要作用 | 注意事项 |
| --- | --- | --- |
| Wiktionary | 英文释义、词性、词形、词族/部分搭配 | 文本多采用 CC BY-SA / GFDL；保留出处、许可信息，注意独立媒体/引用许可 |
| Princeton WordNet | 按义项组织的近义/反义及词义网络 | 遵守 WordNet 许可和归属要求；可能不适合直接给英语学习者展示原始抽象释义 |
| Tatoeba | 英文例句 | 文本通常需要 CC-BY 2.0 FR 署名；音频可能具有**不同许可** |
| YouGlish | 真实语境视频 | Widget/API 开放不等于可随意集成到移动应用；事先核查官方政策 |

开发要求：

1. 设计 **DictionaryProvider / ExampleProvider / PronunciationProvider / VideoProvider** 等抽象层，防止绑定某一个数据源。
2. 数据条目保留**来源、授权、引用链接/必要署名**；不要未经授权复制牛津、柯林斯等商业词典内容。
3. 不得把 WordNet 的同义词无区分地塞给整个词条；尽量按 sense/义项匹配。
4. 异形词（walked → walk）、派生词（creative → create）、同形异义、词性、短语、标点规范化需分别处理；**去重不能误合并不同义项或不同短语**。
5. 无数据时显示缺失或可用的替代来源，不得以模型编造解释、例句或视频作为真实词典内容。
6. 例句难度排序可先采用可解释的启发式，后来再优化；不要把“2–4 条每义项”误读为每个生僻义项都必然有这么多合法例句。

官方出处：
- https://en.wiktionary.org/wiki/Wiktionary:Copyrights
- https://wordnet.princeton.edu/license-and-commercial-use
- https://en.wiki.tatoeba.org/articles/show/faq

## 7. 技术架构（**建议，不是用户已经决定的框架**）

建议以**移动优先的 TypeScript Web 应用**实现，优先保证 iPhone 真机体验。

候选技术：

- 前端：React + Vite + TypeScript（建议）；响应式设计、PWA manifest 与 standalone 模式。
- 样式：轻量样式系统；UI 细节尚未与用户确认，避免提前搞复杂视觉系统。
- FSRS：官方 `ts-fsrs`（**按当前 v6 / FSRS-7 API 文档**）；目前官方文档要求 Node.js >=24，Codex 应先检查开发机版本及依赖兼容性。
- 同步存储方案 A：Supabase Auth + PostgreSQL（开发快）；**Free 实例 7 天低活跃可能暂停**，须做好恢复/迁移/导出方案。
- 同步存储方案 B：Cloudflare Workers + D1 等（可减少平台数量，但开发复杂度及资源额度需评估）。
- 前端静态托管：Cloudflare Pages 可以使用；Cloudflare 官方对新项目更推荐 Workers，最终二选一即可，不要同时引入两套后端。
- 优先实现**合法稳定的词库导入/索引**，不要无计划将整套大型词典直接打包到初始前端，影响移动端加载。
- 数据模型建议：`dictionary_entries`, `senses`, `examples`, `lexical_relations`, `word_forms`, `phrases`, `vocabulary_lists`, `user_learning_items`, `review_logs`, `search_history`, `user_settings`。具体可调整。

关键数据分离：

- **词典内容**（相对静态、共享）与**个人学习数据**（私有、可同步）分库/分表。
- **词条 identity**（lemma / phrase）与**义项 identity**（sense）分开；学习卡可以先按词条，保留将来支持一词多义卡的可能性。
- **手动掌握标志**与 **FSRS card state** 分开；保留完整 review log。
- 同步采用稳定 ID、updated_at、必要的版本/冲突规则；严禁多设备并发修改导致复习日志丢失。
- 含用户数据的 API 必须使用认证和按用户隔离的数据库权限规则；不要把 service role key 之类的服务端密钥写进前端。
- 在设置中提供**个人数据导出/备份**，避免免费服务暂停造成数据难以恢复。

参考：
- https://developers.cloudflare.com/pages/
- https://supabase.com/docs/guides/platform/free-project-pausing
- https://open-spaced-repetition.github.io/ts-fsrs/guide/

## 8. UI 设计：当前尚未正式讨论

产品页面和导航结构**尚未由用户最终确认**，以下只是下一阶段可用于原型的草案：

1. **搜索 / 词典首页**：搜索框、最近查询、每日学习入口。
2. **词条详情页**：词头及美/英发音 → 分义项英文解释/例句/折叠中文 → 常见搭配 → 内嵌视频 → 近反义词/词族/变形 → 加入学习。
3. **今日学习页**：复习优先、新词数量灵活调节、今天进度。
4. **复习卡片页**：只显示英文词 → 提示英文例句 → 答案 → FSRS 评分。
5. **词库 / 历史 / 导出页**：按来源、状态、日期筛选，批量处理与复制。
6. **设置页**：US/UK 口音、记忆保持率、同步状态、数据备份。

在用户确认之前，不要把页面顺序、导航形式、配色、App 名称定死。

## 9. 明确不做 / 延后

- **不做 App 内 AI 问答**，不接 AI 付费 API 用于实时解释或生成文章。
- **不做熟词抽查模式**（已经明确延后）。
- **不强求完整离线词库**（低优先级）。
- 不急于 App Store 原生上架，不急于购置域名。
- 暂不扩展到社交、排行榜、课程、商业订阅等需求。

## 10. 需要优先验证的风险与开放问题

1. **YouGlish 授权**：官方移动应用许可条款与个人 PWA / Web Clip 是否涵盖在内；在许可不明时先做 VideoProvider/外链降级。
2. **词典版权和质量**：每个来源的内容复用条件；真实可用的英英释义、分义项例句、词形、近反义词覆盖率。
3. **云端长期可靠性**：Supabase 免费暂停、备份策略、国内访问体验，或 Cloudflare 替代方案。
4. **iOS PWA 真机验证**：全屏、音频播放、跨源嵌入、状态保持、分享/复制、返回导航。
5. **登录方式**：使用邮箱 OTP、密码或其他方式尚未敲定；希望对个人用户尽量简洁。
6. **系统单词词库**：四六级/雅思/托福哪些优先、词表版权/整理来源、导入格式尚未确定。
7. **UI 视觉风格**：还没讨论导航结构、主题配色、首页布局。
8. **离线范围**：现在属于未来优化项，不应阻碍主流程发布。

## 11. 推荐实施里程碑与验收

**M0｜产品基础与技术验证**
- 创建仓库，确认 Node/依赖版本与部署方案。
- 用 5–10 个**明确标为测试数据**的样例词/短语打通首页、详情页、词条跳转、中文隐藏。
- 验证 iPhone 的 PWA 安装和真实设备体验；搭建视频适配器空实现和合法兜底。
- 验收：可搜索样例单词和短语、进入详情页、点击关联词再返回、中文默认隐藏。

**M1｜词典内容与发音**
- 接入合法词典数据、义项/例句/词族/词形/短语关系；实现 US 默认发音与 UK 切换。
- 接入并验证可用朗读方案；若无音频则明确降级。
- 验收：词典内容**可追溯到来源**，词汇关系不乱配，短语拥有独立详情页。

**M2｜学习、FSRS、导出**
- 双轨学习与来源标签、灵活的新词目标、查询历史和学习词库分离。
- FSRS 全流程、例句提示限制评分、手动已掌握/恢复；学习日志留存。
- 日期筛选、一键去重导出单词和短语。
- 验收：提示后不能评 Good/Easy；“已掌握”不进入复习；导出不混入仅查询的词。

**M3｜云同步与稳定性**
- 个人账户登录、iPhone/Windows 双设备同步、同步冲突处理、数据导出备份。
- 验收：A 设备添加/复习/标记掌握，B 设备能见到一致状态；不会重复添加或覆盖日志。

**M4｜YouGlish 与安装完善**
- 在确认授权和政策的前提下，嵌入视频、口音切换、按需加载、无结果兜底；完成 iPhone Safari PWA 真机测试。
- 可选提供 `.mobileconfig` Web Clip 方式；它不是原生应用，也不应被误宣传。
- 验收：视频不影响无视频时的正常查词；无授权时保留合规外链功能。

> 可以调整里程碑顺序：如果登录/同步是用户最优先实际使用诉求，可提前 M3 的最小化版本；但不要一次性开工所有模块。
